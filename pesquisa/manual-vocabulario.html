Parte 1 Você monta, uma vez só

Meia hora, e só se repete quando o time revisar as decisões. Enquanto o glossário não estiver publicado, o linter não tem o que ler — então esta parte vem antes de chamar o time.

  1. Abra o Triador e compartilhe

    claude.ai/code/artifact/c06dc16d… — no menu de compartilhar da página, libere para quem você quiser.

    Quem abre o link já pode triar. Não precisa de permissão de edição — essa permissão só governa quem publica uma versão nova do app, não quem registra decisões.

  2. Espere a triagem acontecer

    As decisões são compartilhadas em tempo real: o que uma pessoa marca, as outras veem. O indicador no topo diz compartilhado quando está sincronizando.

    Não precisa de consenso em tudo. Termo que gerar discussão vai para decidir e vira pauta — é esse o output que interessa para a conversa do Design System.

  3. Exporte o glossário

    Botão Exportar glossário, no topo à direita. Baixa um glossario.json só com os termos que alguém decidiu.

    Só exporta o que foi decidido. Termo que ninguém tocou fica de fora — o linter não vai reclamar dele. Isso é de propósito: sugestão automática não vira regra.

  4. Publique o arquivo numa URL

    O plugin busca o glossário por HTTP, então ele precisa estar num endereço público. O caminho mais curto é um gist:

    gist.github.com → cole o conteúdo do JSON → nome do arquivo glossario.json → Create public gist → botão Raw → copie a URL.

    Tire o hash da URL. O botão Raw devolve um link com um código longo no meio, que aponta para aquela versão e nunca muda. Apagando esse trecho, a URL passa a servir sempre a versão mais recente — e atualizar o glossário deixa de exigir mexer no plugin. 

    fixa  …/a1b2c3d4e5f6…/glossario.json
viva  …/glossario.json

  5. Coloque a URL dentro do plugin

    Abra pesquisa/linter-figma/code.js e preencha a linha do topo: 

    const DEFAULT_URL = 'https://gist.githubusercontent.com/…/glossario.json';

    Assim o plugin já abre apontando para o lugar certo, e ninguém do time precisa colar nada. Se o endereço não for gist.githubusercontent.com, raw.githubusercontent.com ou um github.io, acrescente o domínio em manifest.json → networkAccess.allowedDomains.

  6. Publique como plugin privado da organização

    Importe a pasta uma vez no seu Figma Desktop (Cmd + / → Import plugin from manifest…), e então, na lista de Plugins → Development, use Publish no plugin.

    No formulário, escolha publicar para a organização, não para a Community. Plugin privado não passa pela revisão do Figma — sai no ar na hora.

    O manifesto muda. Ao publicar, o Figma grava um id dentro do seu manifest.json. É esse id que identifica o plugin nas próximas versões — commite o arquivo depois de publicar.

Parte 2 O time tria

Só navegador. Nada para instalar.

  1. Abrir o link

    Abre em qualquer navegador, inclusive no celular.

  2. Ler a linha do termo antes de decidir

    Cada termo mostra quantas vezes aparece, em quais produtos, e três exemplos reais de tela. A coluna do portal é o sinal mais útil: se o marketing usa o termo, o público entende o termo.

  3. Escolher uma das três

    DecisãoQuandoO linter faz
    manter É o vocabulário do jogador. Trocar afastaria. Ignora.
    traduzir Detalhe de implementação vazando para a interface. Aponta e sugere o substituto.
    decidir Comunica, mas é técnico. Precisa de conversa. Aponta com a nota. Nunca corrige.

  4. Preencher “usar no lugar” em tudo que for traduzir

    É esse campo que vira a correção de um clique no Figma. Sem ele, o linter só sinaliza e a pessoa fica sem saber o que escrever.

  5. Usar a aba Inconsistências

    Ela mostra os conceitos que já têm mais de um nome no produto, e em quais telas cada nome aparece. É o material mais forte para levar à discussão: não é opinião, é o produto se contradizendo.

Parte 3 Quem desenha usa

Nada para baixar. Como o plugin é publicado na organização, ele já está disponível para todo mundo — funciona no navegador e no desktop.

  1. Achar o plugin

    Cmd + / (ou Ctrl + /) e digitar Linter. Ele aparece entre os recursos da organização.

  2. Rodar

    A URL do glossário já vem preenchida. Selecione as camadas que quer conferir — ou não selecione nada, e ele varre a página inteira. Depois, Verificar.

  3. Resolver a lista

    Cada achado tem Ir até a camada, que seleciona e centraliza no canvas. Quando a troca é segura, aparece também Corrigir para “…”.

O que ele corrige sozinho

A troca automática só acontece quando o texto inteiro é o termo, com sufixo opcional entre parênteses. No meio de uma frase, trocar uma palavra pode quebrar a concordância — aí ele aponta e deixa a decisão com quem escreve.

Diga isto ao time junto com o link

Duas ressalvas que evitam a ferramenta ser lida como mais do que é.

Texto no Figma quase sempre é mock

O que chega ao usuário é a string no sistema de i18n, não a camada do Figma. O linter pega o desvio cedo, no desenho — mas não impede o termo errado de entrar no produto. A alavanca real está na criação da string. Este plugin é complemento disso, não substituto.

O linter não decide nada

Ele só repete o que o time marcou no Triador. Discordou de um apontamento? A conversa é sobre a decisão no Triador, não sobre o plugin. Mudou a decisão, exporte e republique o glossário: todo mundo passa a ver o novo critério na próxima verificação.

Quando der errado

“Não consegui carregar” ao verificar
A URL não está pública, ou o domínio não está em networkAccess.allowedDomains no manifest.json. Teste a URL numa aba anônima: se você vê o JSON cru, o plugin também vê.
Atualizei o glossário e o plugin mostra o antigo
Duas causas. A URL pode ter o hash de versão no meio — tire. Ou o cache do GitHub ainda não virou: costuma levar alguns minutos.
Mudei o código e o time continua na versão antiga
Alterar os arquivos na sua máquina mexe só na sua cópia de desenvolvimento. Para o time ver, é preciso publicar de novo pelo Publish.
O plugin sumiu do meu menu Development
A pasta local foi movida ou apagada — o Figma guarda o caminho, não os arquivos. Importe de novo pelo manifest.json. Isso vale só para a sua cópia de desenvolvimento; a versão publicada na organização não depende dessa pasta.
Nenhum botão “Corrigir” aparece
Os termos traduzir estão sem o campo “usar no lugar” preenchido no Triador, ou os textos estão todos em frase — e em frase ele nunca corrige sozinho.
O Triador diz “local — decisões não são compartilhadas”
A sincronização não subiu nessa sessão. O que a pessoa marcar não vai chegar ao resto do time. Recarregue a página antes de triar muita coisa.
